## 決着の記録

**差し戻さず、資料そのものを開いて決めた。** 争点が3件で、決め手になる頁が特定できていたためである。

| 争点 | 分かれ方 | 決着 |
|---|---|---|
| Python の要求版 | claude と codex が `>=3.10`、Antigravity が `>=3.12` | **`>=3.10` が正しい。** PyPI の JSON（`requires_python`）と原本の `pyproject.toml` の両方で確かめた。Antigravity が挙げた根拠は「導入手順の頁」だが、その頁に最低版の記載は無い。conda の例に `python=3.14` があるだけである |
| 日本語の検索の分かち書き | claude は「0.0.52 で対応済み」、Antigravity は「実装の記述が無い」、codex は「範囲が同じとは断定できない」 | **0.0.57 を動かして決着した。** `language = "ja"` を設定して作ると、検索の索引に `config.lang: ["ja"]` が入り、検索の実装に `Intl.Segmenter` を `granularity:"word"` で使う箇所がある。**分かち書きは動く。ロードマップの Stemming and segmentation は別の範囲を指す** |
| 日本語の見出しのアンカー | claude は「既定で壊れる」、codex は「断定できない。受入試験が要る」 | **codex の求めに応じて 0.0.57 で受入試験を行い、決着した。** 既定では `id="_1"` `id="_2"` のような通し番号になり、本文中の参照も同じ番号を指す。`toc.slugify` に `pymdownx.slugs.slugify` を指定すると見出しの語がそのまま ID になる |

**この3件が突き合わせで得られたものである。** 1件は誤った数値を捕まえ、2件は自分の踏み込みすぎを差し戻した。

## モデルの選択で守れないこと

**推論向けのモデルを選んでも、数値の誤りは消えない。** Antigravity は `gemini-3.1-pro-high` で `requires-python` を `>=3.12` と答えた。正しくは `>=3.10` である。挙げた根拠は「導入手順の頁」だが、その頁に最低版の記載は無い。

**版数と日付は、配布物の登録情報で裏を取る。** モデルの選択はその代わりにならない。この結果は `tools/agy.sh` の注記と、依頼文の型へ反映した。

## 残った穴

- 提供終了後に Material for MkDocs のリポジトリがどうなるかは、どの道具も根拠を出せなかった
- 反復構築の速さは、ページ数を増やした測定をしていない。手元の14ページでは利点が出ない
- 公式の説明頁の多くに公開日が無い。対象期間（2025-11-01 以降）に入るかを確かめられていない
