# テーマを調査し、出典を残して保管し、再利用できる形へ整える

**調査は二段で行う。** 第1段で出典を失わない調査パックを作って保管する。第2段でそれを分析し、文書の材料へ整形する。

**分析を先に書き、根拠を後から付けてはならない。** 台帳に無い主張は書かない。

## 使う場面

- ユーザーが「〜について調査して」「〜について調べて」「資料を集めて」と言ったとき
- 保管済みの調査パックを基に、分析や新しい文書を求められたとき

**使わない場面**: 外部調査を伴わない作業。手元のファイルだけを読む要約や書き換えが該当する。

## 手順

写して、終わったものに印を付ける。

```text
- [ ] 手順1: 調査の範囲を決める
- [ ] 手順2: 保管済みの調査パックを確かめる
- [ ] 手順3: 資料を集め、本文を読む
- [ ] 手順4: 調査パックとして保管する
- [ ] 手順5: 根拠から分析する
- [ ] 手順6: 文書へ整形する
```

手順6は、文書の作成を求められたときだけ行う。

### 手順1 調査の範囲を決める

依頼から次を読み取る。書かれていない項目は仮定を置き、その仮定を調査パックに明記する。

| 決めること | 例 |
|---|---|
| 答える問い | Docker Compose を本番環境で使ってよいか |
| 利用目的 | `docs/` に置くツール説明文書の材料にする |
| 対象期間 | 2024-01-01 以降に公開された資料 |
| 想定読者 | 本番環境の構成を決めるバックエンド開発者 |

**質問して止まるのは、仮定を置くと成果物が無駄になる場合だけとする。** それ以外は仮定を書いて進める。

ユーザーが期間・情報源・件数・成果物の形式を指定したときは、その指定を優先する。

調査の時点は年月日で書く。「最新の」のような語を使わない。

### 手順2 保管済みの調査パックを確かめる

同じ問いを扱う調査パックが残っていれば、集め直さない。

```bash
ls research/ 2>/dev/null || echo "調査パックはまだ無い"
```

見つかったら調査日、資料台帳、埋まらなかった問いを読む。利用目的を支える情報がそろっていれば、手順5から始める。

### 手順3 資料を集め、本文を読む

WebSearch で候補を探し、**WebFetch で本文を開いて確かめる。**

**検索結果の見出しと要約だけを根拠にしない。** 本文へ到達できなかった資料は、台帳に「未閲覧」と記して残す。消さない。

| 守ること | 理由 |
|---|---|
| 一次情報を優先する | 解説と報道は背景と比較に使う |
| 独立した複数の資料で照合する | 変わりやすい事柄と論争のある事柄で食い違いが出る |
| 組織自身の発表と第三者の検証を分ける | 利害が違う |
| 事実と資料側の主張と自分の推論を混ぜない | 後から根拠をたどれなくなる |
| 引用は文言そのものが重要な箇所に絞る | それ以外は要約する |

資料が食い違うときは、平均して1つの事実にしない。相違点と、その理由の見立てを両方残す。

**集め終える基準**: 次の3つがそろったときとする。

- 主要な問いのすべてに根拠が付いている
- 重要な反対意見が台帳に入っている
- 残る不明点を言葉で説明できる

同じ内容の資料だけが増え始めたら、3つがそろう前でも打ち切る。

### 手順4 調査パックとして保管する

保管先は `research/<YYYY-MM-DD>-<テーマ>/pack-claude.md` とする。型は `reference/research-pack.md` にある。写して埋める。

**道具ごとに1ファイルにする。** Codex や Antigravity にも同じ問いを投げるときは、`pack-codex.md` と `pack-antigravity.md` を同じフォルダへ並べる。突き合わせの手順は `cross-agent-research` にある。

**`research/` を使う理由**: ドキュメント標準が生の出典ノートを置く場所である。`.doclint.yml` の検査対象にも入っていない。要約前の原文や長い引用を置いても、検査で落ちない。

ユーザーが別の保管先を指定したときは、そちらへ置く。

### 手順5 根拠から分析する

**資料の順ではなく、問いの順に統合する。** 1資料1段落にしない。

結論1件ごとに、根拠となる資料IDをたどれるようにする。推論には「推論」と書き、その推論を支える事実を添える。

確からしさは、次の5点から決める。

| 見る点 | 高くなる例 |
|---|---|
| 根拠の直接性 | 一次情報が直接その事実を述べている |
| 発行主体の利害 | 主張者と検証者が別である |
| 公開時期 | 対象の版と時期が合っている |
| 独立性 | 引用関係の無い資料である |
| 一致数 | 独立した3件以上が一致している |

**資料に無い内容で空白を埋めない。** 確かめられない事項は「未確認」と書く。

### 手順6 文書へ整形する

調査パックの「再利用素材」を起点に、読者と目的へ合わせて組み直す。

- 調査の過程は本文へ持ち込まない。求められたときだけ付録に置く
- 主張と出典の対応、留保、調査の年月日は残す
- 根拠が足りない箇所だけ、手順3へ戻って追加で調べる

**このリポジトリの `docs/` に置くツールの説明文書を書くときは、`writing-guidebook-tool-docs` に従う。** 型と一覧の直し方と検査の手順は、そちらにある。

## 判定の基準

次をすべて満たせば完了とする。1つでも欠ければ未完了とする。

- [ ] 調査パックが保管されている。または、ユーザーが保管先を拒んだ記録がある
- [ ] 台帳の全資料に、取得日と種別と制約が付いている
- [ ] 本文を読めなかった資料が「未閲覧」と記されている
- [ ] 結論1件ごとに根拠の資料IDが付いている
- [ ] 事実と推論が語で区別されている
- [ ] 食い違いが平均されず、両論のまま残っている
- [ ] 置いた仮定が調査パックに書かれている
