# 調査パックの型

この型を `research/<YYYY-MM-DD>-<テーマ>/pack.md` に写して埋める。
丸かっこの例文と、書き方を指示する引用行は消す。

## 目次

| 節 | 何を書くか |
|---|---|
| 調査概要 | 問い、利用目的、範囲、仮定、調査日 |
| 要約 | 先に読むべき結論と、重要な留保 |
| 資料台帳 | 集めた資料1件ごとの出典と制約 |
| 分析結果 | 結論と、その根拠となる資料ID |
| 食い違いと不明点 | 資料間の相違、埋まらなかった穴 |
| 再利用素材 | 文書を書くときにそのまま使える材料 |

---

## 調査概要

| 項目 | 内容 |
|---|---|
| 調査日 | （例: 2026-08-31） |
| 答える問い | （例: Docker Compose を本番環境で使ってよいか） |
| 利用目的 | （例: docs/docker-compose.md の材料にする） |
| 対象期間 | （例: 2024-01-01 以降に公開された資料） |
| 想定読者 | （例: 本番環境の構成を決めるバックエンド開発者） |
| 置いた仮定 | （例: 対象は Linux のみとした。依頼に指定が無かったため） |

## 要約

> 結論を先に書く。留保は結論と同じ場所に書く。あとの節へ回さない。

（例: 単一ホストなら本番利用の実績がある。複数ホストへ広げる用途は想定されていない。）

## 資料台帳

> 本文を開いて読んだものだけを「閲覧済」とする。読めなかったものも消さずに残す。

| ID | 資料と日付 | 発行 | 種別 | 裏付ける内容 | 制約 |
|---|---|---|---|---|---|
| S-01 | （例: Compose の本番利用ガイド 2025-04-10 取得 2026-08-31） | （例: Docker 社） | （例: 提供元の文書） | （例: 単一ホスト向けと明記している） | （例: 提供元自身の説明であり第三者の検証ではない） |
| S-02 | （例: 未閲覧の資料） | （例: 不明） | （例: 記事） | （例: なし） | （例: 本文へ到達できず未閲覧） |

**種別に使う語**

| 種別 | 何を指すか |
|---|---|
| 一次情報 | 当事者が出した原本 |
| 提供元の文書 | 製品を作った組織の説明 |
| 査読つき研究 | 査読を経た論文 |
| 公開仕様 | 標準化された仕様書 |
| 記事・報道 | 第三者による解説 |
| 個人の記録 | 個人の実測や体験 |

## 分析結果

> 資料の順ではなく、問いの順に並べる。結論1件ごとに根拠のIDを付ける。

| 結論 | 根拠ID | 解釈 | 確からしさ |
|---|---|---|---|
| （例: 単一ホストでの本番利用は支持される） | （例: S-01 S-03） | （例: 提供元と第三者が一致している） | （例: 高い） |
| （例: 複数ホストへは向かない） | （例: S-01） | （例: 推論。提供元が想定外と書いているだけである） | （例: 中くらい） |

**確からしさの決め方**: 根拠の直接性、発行主体の利害、公開時期、独立した資料の一致数を見る。

## 食い違いと不明点

> 食い違いを平均して1つの事実にしない。両方を残し、理由の見立てを添える。

| 事項 | 資料Aの主張 | 資料Bの主張 | 見立て |
|---|---|---|---|
| （例: 再起動時の挙動） | （例: 自動復帰する） | （例: 復帰しない） | （例: 対象の版が違う） |

**埋まらなかった問い**

- （例: 日本語での事例が見つからなかった。英語の資料だけで判断している）

## 再利用素材

> ここが文書を書くときに開く節である。調査の過程は書かない。

| 項目 | 内容 |
|---|---|
| 想定読者 | （例: 構成を決めるバックエンド開発者） |
| 中心の主張 | （例: 単一ホストなら使ってよい） |
| 使える数値 | （例: 起動にかかる時間 2.1 秒） |
| 使える固有名詞 | （例: Docker Compose v2.29） |
| 図表の候補 | （例: 単一ホストと複数ホストの比較表） |
| 書くときの注意 | （例: 提供元の文書だけを根拠にした箇所を明示する） |
