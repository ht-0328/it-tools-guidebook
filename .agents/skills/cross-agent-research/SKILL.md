# 同じ問いを複数の道具に調べさせ、突き合わせて判定を1つにする

**目的は、答えを増やすことではない。食い違いを見つけることである。**

3つの道具が一致した箇所は確からしさが上がる。**食い違った箇所こそが、追加で調べるべき場所である。**

**多数決で決めてはならない。** 3つのうち2つが同じことを言っても、根拠が同じ1件なら独立していない。判定は根拠の中身で決める。

## 使う場面

- ユーザーが「Codex にも調べさせて」「複数のAIで調べて」「突き合わせて」と言ったとき
- `research/<日付>-<テーマ>/` に、道具の違う調査パックが2つ以上あるとき

**使わない場面**: 1つの道具だけで調べるとき。そのときは `research-and-synthesize` を使う。

## 手順

写して、終わったものに印を付ける。

```text
- [ ] 手順1: 問いと成果物の形を固める
- [ ] 手順2: 依頼文を1本作る
- [ ] 手順3: 道具ごとに投げ、調査パックを回収する
- [ ] 手順4: 突き合わせ表を作る
- [ ] 手順5: 食い違いを各道具へ差し戻す
- [ ] 手順6: 判定をまとめる
```

### 手順1 問いと成果物の形を固める

**分担の前に、問いを1文へ縮める。** 問いが道具ごとにずれると、突き合わせができない。

| 決めること | 例 |
|---|---|
| 答える問い | Docker Compose を本番環境で使ってよいか |
| 利用目的 | `docs/docker-compose.md` の材料にする |
| 対象期間 | 2024-01-01 以降に公開された資料 |
| 成果物 | `research/2026-08-31-docker-compose/pack-<道具名>.md` |

**道具ごとに違う切り口を割り当ててはならない。** 同じ問いを同じ条件で投げる。切り口を分けると、一致も食い違いも判定できなくなる。

### 手順2 依頼文を1本作る

**3つの道具へ、同じ本文を渡す。** 型と書き方は `reference/agent-brief.md` にある。

依頼文には、調査パックの節の並びを埋め込む。**受け取る形をそろえないと、手順4の表が作れない。**

**依頼文に道具固有の記号を書かない。** `/名前` は Claude Code、`$名前` は Codex、`@名前` は ChatGPT の記法である。渡す先が違えば、ただの文字列になる。

### 手順3 道具ごとに投げ、調査パックを回収する

自分の分は `research-and-synthesize` に従って調べ、`pack-<自分の道具名>.md` として保管する。

**自分以外の2つへ投げる。** 命令は `reference/agent-brief.md` の「道具ごとの投げ方」にある。3つの道具の命令がそこに並んでいるため、自分の行を飛ばして残る2行を使う。

**回収したファイルは、開いて中身を確かめる。** 空のファイル、断り文、途中で切れた出力を、調査パックとして数えない。

**回収できなかった道具は、消さずに記録する。** 「Antigravity は応答が空だった」と書く。書かないと、次にやる人が同じことを試す。

### 手順4 突き合わせ表を作る

**主張1件ごとに、3つの道具の答えを横に並べる。** 道具ごとに節を分けない。分けると比較できない。

| 主張 | Claude Code | Codex | Antigravity | 根拠は独立か |
|---|---|---|---|---|
| （例: 単一ホストなら本番で使える） | （例: 支持。S-01） | （例: 支持。S-01） | （例: 言及なし） | （例: **同じ1件。独立していない**） |

**「根拠は独立か」の列を空にしない。** ここが多数決を防ぐ唯一の仕掛けである。

道具が挙げた出典の URL を突き合わせ、同じものなら独立していないと書く。

### 手順5 食い違いを各道具へ差し戻す

**食い違った主張だけを取り出し、相手の主張を添えて投げ直す。** 全部を投げ直さない。

差し戻しの依頼文は、次の3つを含める。

1. 争点となっている主張を1文で書く。
2. 他の道具が挙げた根拠と、その出典を書く。
3. 「この根拠を踏まえて、自分の結論を保つか変えるかを述べる。変えないなら理由を書く」と求める。

**相手の結論だけを見せて、根拠を隠さない。** 根拠を隠すと、相手は同調するだけになる。

差し戻しは1往復までとする。**2往復目からは、資料そのものを自分で開いて確かめるほうが速い。**

### 手順6 判定をまとめる

`research/<日付>-<テーマ>/verdict.md` に書く。型は `reference/verdict.md` にある。

| 判定 | 付ける条件 |
|---|---|
| 確定 | 独立した根拠が2件以上あり、3つの道具が反論しなかった |
| 暫定 | 根拠は1件だけである。または反論が残っている |
| 未確認 | どの道具も根拠を出せなかった |

**「未確認」を消さない。** 埋まらなかった穴は、文書へ持ち込むときに読者へ伝える。

判定に使わなかった主張も、突き合わせ表の中に残す。**捨てると、後から別の用途で使えなくなる。**

## 判定の基準

次をすべて満たせば完了とする。1つでも欠ければ未完了とする。

- [ ] 3つの道具へ同じ依頼文を渡した。渡せなかった道具は理由が書かれている
- [ ] 回収したパックが `research/<日付>-<テーマ>/pack-<道具名>.md` にある
- [ ] 突き合わせ表が、道具別ではなく主張別に並んでいる
- [ ] 「根拠は独立か」の列がすべて埋まっている
- [ ] 食い違いが1件以上あるなら、差し戻した記録がある
- [ ] `verdict.md` の各行に「確定」「暫定」「未確認」のいずれかが付いている
