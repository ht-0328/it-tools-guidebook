## 結論

**答える問いは1つである。いま使っている Material for MkDocs から Zensical へ移るか。**

**移る準備は始める。ただし、いま全面的に置き換えない。**

理由は3つある。

1. **期限がある。** Material for MkDocs の提供は 2026-11-05 に終わる。
2. **移行先は1つに決まっている。** Zensical は同じ組織が作っており、提供元が移行先として案内している。
3. **まだ Alpha である。** 0.0.57 の分類は `Development Status :: 3 - Alpha` で、MkDocs のプラグインもそのままでは動かない。

**始め方**: 新しい企画と、プラグインに頼っていない企画から試す。既存の大きな企画は、下の「採用してよい条件」を満たしてから移す。

## Zensical は何をするツールか

Zensical は、Markdown から検索とナビゲーションを備えた文書サイトを作るツールである。

**MkDocs と Material for MkDocs の役割を1つにまとめている。** 従来は、生成器（MkDocs）とテーマ（Material for MkDocs）を別々に選び、版を合わせる必要があった。

中核は ZRX という Rust 製の機構である。変更したファイルだけを作り直す差分構築と、処理の並列化を担う。

## Material for MkDocs との関係と、移行の期限

**同じ組織が作った後継である。** Material for MkDocs は保守だけの状態に入っている。

| 時点 | 何が起きるか |
|---|---|
| 2026-11-05 まで | 重大な不具合と安全性の問題だけを直す。新機能は Zensical へ |
| 2026-11-05 | 提供終了 |

**提供元は「既存サイトの即時移行は不要」としている。** 一方で、新しい企画と長期の計画では Zensical の評価を勧めている。

**提供終了後にリポジトリがどうなるかは分かっていない。** アーカイブされるのか、有志の保守を受け入れるのかを、3つのAIによる調査でも確かめられなかった。

## 何が速くなり、何が速くならないか

**速くなるのは、2回目以降の構築である。**

| 構築の種類 | 提供元の記録 |
|---|---|
| 反復構築（`serve` 中に文書を直したとき） | MkDocs の4〜5倍 |
| 初回構築 | **MkDocs より遅くなる場合がある** |

**この数値は提供元のものであり、第三者の再測定ではない。** 14ページ規模で測った手元の記録では、反復構築の利点は出なかった。差が出るのはページ数が多い場合である。

メモリについては、0.0.54（2026-08-13）が大規模サイトのピーク使用量を8〜10分の1にしたという提供元の記録がある。**これも独立した検証は無い。**

## 採用してよい条件

**次の4つをすべて満たせるなら移してよい。** 1つでも欠けるなら、その企画はまだ早い。

1. Alpha の更新と不具合を引き受け、版を固定できる
2. 使っている Markdown 拡張とプラグインを、実サイトで検証できる
3. CI で構築の失敗、リンク切れ、検索、画面の差分を検査できる
4. 初回構築と反復構築の時間を、自分のサイトで測れる

## 導入に要るもの

| 要るもの | 用途 | 確認方法 |
|---|---|---|
| Python 3.10 以上 | Zensical の実行 | `python3 --version` が `3.10` 以上を表示する |
| pip または uv | Zensical の導入 | `pip --version` が版を表示する |

**`Python >=3.10` は、配布物の登録情報と原本の `pyproject.toml` の両方で確かめた値である。** 提供元の導入手順の頁には最低版の記載が無いため、そこだけを見ると分からない。

ライセンスは MIT である。**ただし編集環境の Zensical Studio だけは独自の商用 EULA であり、別製品として扱う。**

## 手元で動かす手順

**開始条件**

- [ ] Python 3.10 以上が入っている
- [ ] 空のディレクトリを1つ用意している

**手順**

1. `python3 -m venv .venv` を実行する
2. `source .venv/bin/activate` を実行する
3. `pip install zensical` を実行する
4. `zensical new .` を実行する
5. `zensical serve` を実行する
6. ブラウザで `http://localhost:8000` を開く

**成功したとき**: 手順4で次の4つが作られる。手順6でトップページが表示され、文書を直すと表示が入れ替わる。

```text
.github/workflows/docs.yml
docs/index.md
docs/markdown.md
zensical.toml
```

命令は3つだけである。`zensical new` で企画を作り、`zensical serve` で表示を確かめ、`zensical build` で `site/` へ書き出す。

**`zensical serve` は公開に使わない。** プレビュー専用である。公開には nginx、Apache、CDN、GitHub Pages などを使う。

## 日本語で必要になる2つの設定

**書かないと壊れる。** どちらも 0.0.57 で作った生成物を調べて確かめた。

| 症状 | 書く設定 |
|---|---|
| 見出しのアンカーが `_1` `_2` になり、本文中の参照が切れる | `toc.slugify = { object = "pymdownx.slugs.slugify", kwds = { case = "lower" } }` |
| 全文検索が語で区切られない | `[project.theme]` の `language = "ja"` |

**検索の設定には、紛らわしい点がある。** ロードマップの「Stemming and segmentation」は未完了のままである。しかし `language` を `ja` にすると、生成物の検索の索引に `config.lang: ["ja"]` が入り、検索の実装が `Intl.Segmenter` を語単位で使う。**ロードマップの項目は別の範囲を指している。**

## 移行前に確かめること

**プラグインを1つずつ確かめる。** MkDocs のプラグインはそのまま動かない。Zensical は組み込みのモジュールへ段階的に置き換える方針である。

**提供元のプラグイン一覧は「対応を約束して登録した一覧」であり、実装済みの印ではない。** 一覧に名前があることを、動く根拠にしない。`blog`、`tags`、`git-authors`、`redirects` は 2026-09-01 時点で入っていない。

**設定ファイルは `mkdocs.yml` も読める。** 新しい標準は `zensical.toml` である。ただし `docs_dir` で2点戸惑う。カレントディレクトリを指定できないため別の名前を与える。また `docs_dir` の中だけがサイトになるため、外を指すリンクは書き換えが要る。
